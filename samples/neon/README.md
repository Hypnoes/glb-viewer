# NEON RANGE samples

Prototype GLB snapshots exported from the companion Bevy project
(`fps-demo`). Generated by `tools/asset-export/neon_assets.py`; do not
hand-edit.

| File | Asset ID | Mesh nodes | Triangles | Notes |
| --- | --- | ---: | ---: | --- |
| `weapon_nr01.glb` | WPN_NR01 | 21 | 252 | View-model rifle, `Muzzle` empty node, game camera pose in extras |
| `drone_mk2.glb` | PRP_DRONE_MK2 | 6 | 3,888 | Target drone; hit/lock radii in extras |
| `cover_crate.glb` | PRP_COVER_CRATE | 4 | 48 | Cover crate, cyan trim variant |
| `range_arena.glb` | ENV_RANGE | 146 | 34,472 | Closed range; use its `view_hint` interior camera |
| `drone_mk2.anims.json` | PRP_DRONE_MK2 | — | — | Sidecar animation library: `spawn`, `idle`, `destroy` |

Each root node has `extras.neon_range` with `asset_id`, `source`,
`pivot`, `gameplay_refs`, `units` and (where relevant) `view_hint`.

These are review snapshots, not the final source of truth:

- UV spheres approximate Bevy's ico-spheres.
- Weapon is exported at identity pose/scale; the in-game camera pose is metadata.
- Lights, bloom, fog, HUD, particles and tracers are not exported in the model files.
- `range_arena.glb` includes the six docked drones in rest pose, not hover animation.

`drone_mk2.anims.json` is copied unmodified from
`fps-demo/assets/anims/prp_drone_mk2.anims.json` and is
the sidecar format consumed by `src/neon-anims.js` (schema 1). It is authored
animation data, not a generated GLB: `spawn` and `destroy` are one-shot clips,
`idle` loops, and all three include `emissive_scale` tracks. Recopy it when the
game asset changes.

## Scene/UI development fixtures

The viewer's read-only scene and UI modes prefer the real pack at
`../fps-demo/assets` (the sibling checkout) through `/project-assets/`. When
that checkout is unavailable, these fixtures keep the modes testable:

```text
samples/neon/manifest.json              asset IDs -> the four review GLBs
samples/neon/scenes/range.scene.json    static shell + 4 covers + 6 target slots + lights/camera
samples/neon/ui/theme.json              coarse-preview theme tokens
samples/neon/ui/layout.json             coarse-preview HUD/menu/results tree
samples/neon/ui/strings.en.json         coarse-preview copy
```

The fixture scene mirrors the real `assets/scenes/range.scene.json` values
(camera, lights, fog, bloom, prop transforms, colliders, target slots, spawn) so
the fallback exercises the same loader paths. One caveat: `range_arena.glb` is a
review snapshot that already contains six docked drones, so the fixture shows
duplicate drones when target instancing is on. Append `?targets=0` when using the
fixture if you want the arena snapshot alone. `test/scene-smoke.mjs` records which
source it used in `test/scene-smoke-report.json`.
